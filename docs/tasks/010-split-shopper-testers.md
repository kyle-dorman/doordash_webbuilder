# Task 010 — Split the shopper testers and retire the native runner

**Status** · Closed on November 19, 2026. Both testers passed the cart edit.

Keep one `webbuilder-shopper` package with two entry points. In `scripted`, Python chooses each Playwright action. In `computer_use`, the shopper sees the customer’s request and the browser viewport, chooses its own actions through the SDK’s `ComputerTool`, and replies to the customer. The test supplies the requests and independently decides whether the story passed.

## Implementation plan

1. **Split the testers by who chooses the actions.** Move `runner.py` and the scripted navigation and checkout steps from `browser.py` into `webbuilder_shopper.scripted`. Put the SDK agent, browser tool, customer requests, model-answer parsing, retries, and run reports in `webbuilder_shopper.computer_use`. Keep the story IDs, local storefront and mock setup, private cart and receipt readers, and expected-outcome checks in shared modules. Each tester should run independently of the other.
2. **Run the SDK and the browser on one event loop.** Give `ComputerTool` an async Playwright adapter. Use async Playwright for the scripted steps too, so both testers can call the same private viewport readers. Remove the thread portal, operation queue, and futures that currently relay clicks to a synchronous page. The shopper gets screenshots and the existing permitted browser actions. The grader alone reads page elements during computer-use evaluation and observes mock submissions. Preserve the storefront navigation limits and stop flagged actions before dispatch.
3. **Make one attempt readable from start to finish.** Open the homepage with a fresh browser context, mock, and SDK conversation. Send the customer’s request and opening screenshot. Let the SDK run the shopper until it replies. The test checks any intermediate result, sends the follow-up when the story calls for it, and captures the final viewport before closing the page. Grade the completed mock record after pending checkout requests finish. The suite owns retries. A recorder captures the trace, screenshots, and usage as the attempt proceeds.
4. **Retire the native Responses runner.** Remove its hand-written conversation loop and the code that switches between implementations. Preserve still-needed behavior, including API-error redaction, in the SDK path. Keep both console commands. `run-computer-shopper --site … --feed …` uses the SDK directly. Update the README examples. The original two-runner pilot and its evidence are available at revision `912adcb`. [Task 008 comparison](008-agents-sdk-edit-story.md)
